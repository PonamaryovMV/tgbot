# Архитектура проекта Telegram Wishlist Mini App

Документ описывает модульную структуру репозитория, ответственность каждого файла и потоки данных между клиентом, Cloudflare Workers и Cloudflare KV.

---

## 1. Общая схема взаимодействия

```text
Telegram Mini App / Telegram Bot
              |
              v
    GitHub Pages (статический фронтенд)
    ├── index.html      (HTML-каркас, формы, модальные окна, конфиг API_BASE_URL)
    ├── styles.css      (дизайн-токены, темы Obsidian / Light / Amethyst, адаптивная сетка)
    ├── app-state.js    (SDK Telegram, роутинг deep links, API-клиент, KV-фото, копирование)
    ├── app-social.js   (кастомные группы приватности, подписки, поводы, гибкий шаринг)
    └── app-render.js   (формы, переключатели, фильтрация и рендеринг карточек)
              |
              | HTTPS + X-Telegram-Init-Data
              v
    Cloudflare Workers
    └── worker.js       (проверка HMAC-SHA256, права доступа, KV CRUD, webhook, уведомления)
              |
              v
    Cloudflare KV (env.DB)
    (вишлисты, профили, группы, поводы, участия, подписки, настройки уведомлений, изображения)
```

---

## 2. Назначение файлов репозитория

### Клиентская часть (GitHub Pages)

Фронтенд намеренно разделён на независимые статические файлы без сборщиков и внешних зависимостей, чтобы каждый модуль оставался компактным, читаемым и легко модифицируемым:

| Файл | За что отвечает |
| :--- | :--- |
| `index.html` | Точка входа Mini App. Содержит семантическую разметку трёх рабочих разделов (`Вишлист`, `Я участвую`, `Друзья`), формы добавления/редактирования подарков, модальные окна (редактирование, удаление подарка, переименование/удаление группы, управление поводами, гибкий шаринг), базовую константу `API_BASE_URL` и подключение скриптов. |
| `styles.css` | Все стили интерфейса: CSS-переменные для трёх тем (`dark`, `light`, `amethyst`), адаптивные сетки Bento (`320px` – `1280px+`), карточки подарков, бейджи режимов (`is_crowdfund`, `is_reusable`), чипы поводов и групп, модальные шторки (Bottom Sheet) и toast-уведомления. |
| `app-state.js` | Инициализация `Telegram.WebApp` и `HapticFeedback`; разбор URL-параметров (`?list=...&occasion=...`) и `start_param` (`list_<id>_occ_<id>`); редирект обычных браузерных ссылок в бота; глобальный объект `state`; экранирование XSS; авторизованная загрузка KV-изображений в `Blob URL`; сжатие фото через HTML5 Canvas (`600px`, WebP/JPEG `0.75`); CRUD-запросы к `/api/gifts` и копирование чужих желаний (`copy_gift`). |
| `app-social.js` | Управление подписками и кастомными группами приватности (`create_group`, `rename_group`, `delete_group`, `add_group_member`, `remove_group_member`) через `/api/social`; предупреждение о превращении подарков в общие при удалении единственной группы; выбор аудитории и поводов в формах; управление подборками по поводам (`save_occasion`, `delete_occasion`); модальное окно гибкого шаринга (весь вишлист или конкретный повод). |
| `app-render.js` | Управление формами добавления и редактирования желаний, тегами и уровнями желания; взаимоисключающая логика переключателей «Можно скинуться» и «Можно дарить несколько раз»; синхронизация раздела «Я участвую» (`book`, `crowdfund`, `reusable`); фильтрация по поводам, статусу, цене и категориям; рендеринг карточек подарков и инициализация приложения на `DOMContentLoaded`. |

### Серверная часть и конфигурация

| Файл | За что отвечает |
| :--- | :--- |
| `worker.js` | Единый Cloudflare Worker: проверка подписи и срока действия `X-Telegram-Init-Data` (HMAC-SHA256); HTTP API (`/api/gifts`, `/api/data`, `/api/participations`, `/api/social`, `/api/upload`, `/api/img/<id>`, `/api/config`, `/api/health`); серверная фильтрация приватности по `group_ids`; независимое клонирование KV-изображений при `copy_gift`; обработка Telegram webhook (`/start`, `/notifications`, `callback_query`, `users_shared`); фоновая отправка plain-text уведомлений через `ctx.waitUntil`. |
| `wrangler.toml` | Конфигурация деплоя Cloudflare Worker: имя воркера, дата совместимости, привязка KV namespace (`DB`) и Secrets Store (`BOT_TOKEN`). |
| `package.json` | Метаданные проекта, требование Node.js `>=20`, dev-зависимость `playwright` и npm-скрипты (`test`, `test:worker`, `test:browser`). |

### Тестирование и CI/CD

| Файл | За что отвечает |
| :--- | :--- |
| `tests/worker.test.mjs` | Backend-тесты (20 групп сценариев) на встроенном `node:assert/strict` с `MemoryKV` в памяти и глобальной заглушкой `api.telegram.org`. Покрывают авторизацию, CRUD, приватность групп, поводы, многоразовые подарки, копирование, KV-картинки и уведомления бота. |
| `tests/browser-runner.mjs` | Локальный HTTP-сервер на свободном порту, раздающий статические файлы (`index.html`, `styles.css`, `app-*.js`) для headless Chromium, и оркестратор запуска браузерных сьютов. |
| `tests/browser-telegram.js` | End-to-end сценарии Telegram-режима с моком `window.Telegram.WebApp` и Worker API: deep links с поводами, авторизованные KV-картинки, бронирование, многоразовые подарки, копирование желаний, подписки, гибкий шаринг и обработка ошибок API. |
| `tests/browser-demo.js` | End-to-end сценарии автономного демо-режима (`?demo=1`): CRUD желаний, кастомные группы (создание, переименование, удаление), фильтрация по поводам, многоразовые подарки, приватность ролей, адаптивность вёрстки (`320px` – `1280px`) и редирект браузерных ссылок в бота. |
| `.github/workflows/tests.yml` | Пайплайн GitHub Actions (`ubuntu-24.04`, Node.js 22): параллельный запуск `Backend Worker Tests` и `Browser Playwright Tests` на push/PR в `main` с автоматическим созданием и закрытием GitHub Issues при сбоях. |
| `README.md` | Обзор продукта, рабочие ссылки, описание пользовательского функционала, таблица ключей KV и инструкция по запуску тестов и ручной проверке. |
