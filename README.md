# Telegram Wishlist Mini App

Telegram Mini App для личных вишлистов, бронирования подарков и совместных сборов. Интерфейс работает на GitHub Pages, серверная логика — на Cloudflare Workers, все данные и изображения хранятся в Cloudflare KV.

## Рабочие ссылки

- Бот: [@testpmvbot_bot](https://t.me/testpmvbot_bot).
- Mini App: <https://ponamaryovmv.github.io/tgbot/>.
- Worker: <https://tgbot.ax1ksg94.workers.dev>.
- Явное браузерное демо: <https://ponamaryovmv.github.io/tgbot/?demo=1>.

Обычная браузерная ссылка не открывает демонстрационные данные: она перенаправляет пользователя в настоящего Telegram-бота. Ссылка вида `?list=<ownerId>` преобразуется в deep link `/start list_<ownerId>`, а ссылка на подборку `?list=<ownerId>&occasion=<occasionId>` — в `/start list_<ownerId>_<occasionId>`.

## Функционал

### Для владельца вишлиста

- Личный вишлист привязан к Telegram ID владельца.
- Добавление, редактирование, удаление и архивирование желаний.
- Отметка «Подарили» и возврат подарка из архива.
- Название, необязательные цена, комментарий, категория, ссылка на магазин и фотография.
- Три уровня желания: «Очень хочу», «Среднее хочу», «Пока подождёт».
- До восьми необязательных тегов на подарок, включая быстрый выбор готовых тегов.
- Три взаимоисключающих режима бронирования: одиночная бронь, совместный сбор («Можно скинуться») и многоразовый подарок («Можно дарить несколько раз», `is_reusable`).
- Подборки по поводам (`occasions`): создание, переименование и удаление до 20 поводов, привязка желаний к одному или нескольким поводам и гибкий шаринг ссылки на весь вишлист или конкретную подборку.
- Ограничение видимости отдельного желания одной или несколькими кастомными группами.
- Просмотр статуса «Занято», количества участников сбора и счётчика выбравших многоразовый подарок без раскрытия имён.
- Ссылка для отправки вишлиста или подборки через Telegram.

### Для гостя

- Открытие чужого вишлиста или конкретной подборки по Telegram-ссылке.
- Отображение настоящего имени владельца и его `@username`.
- Бронирование обычного подарка одним гостем и отмена своей брони.
- Независимая отметка участия в многоразовых подарках (`is_reusable`) без блокировки для других гостей.
- Присоединение к совместному сбору и выход из него.
- Копирование любого видимого чужого желания в собственный вишлист («Добавить себе», `copy_gift`) с независимым клонированием KV-изображения.
- Раздел «Я участвую» с одиночными бронями, совместными сборами и многоразовыми подарками.
- Подписка на вишлист прямо со страницы чужого списка.
- Фильтры по поводам, доступности, цене и категории.

«Скинуться» означает только отметку участия. Денежные переводы и платёжные операции в приложении не выполняются.

### Подписки и кастомные группы

- Подписка по `@username` или по Telegram ID из открытого вишлиста.
- Если username ещё неизвестен приложению, бот предлагает встроенный выбор человека в Telegram. Пользователю не нужно самостоятельно узнавать числовой ID.
- Кастомные группы доступа: для новых пользователей создаётся нейтральный стартовый набор («Семья», «Близкие», «Друзья», «Коллеги»), при этом владелец может создавать свои группы (`create_group`), переименовывать (`rename_group`) и удалять (`delete_group`) любые группы. Для старых записей без поля `name` сохраняется обратная совместимость по ID.
- До 20 групп на пользователя, до 200 подписок и до 200 участников в группе.
- Подписка только сохраняет вишлист в интерфейсе и не даёт доступа к приватным желаниям.

### Уведомления от Telegram-бота

- Уведомления о событиях по забронированным подаркам, многоразовым подаркам и совместным сборам: удаление активного подарка, отметка «Подарили», смена формата (`is_crowdfund` / `is_reusable`), изменение важных деталей (название, цена, комментарий, ссылка), а также потеря доступа к подарку при изменении аудитории или исключении из группы (при исключении из группы несколько отменённых подарков группируются в одно сообщение).
- Уведомления подписчикам о появлении новых желаний в вишлисте с учётом настроек видимости подарка (`group_ids`).
- Управление уведомлениями через команду `/notifications` в чате с ботом: раздельное включение и выключение уведомлений о бронях/сборах и о новых желаниях с помощью inline-кнопок.
- Все уведомления отправляются в plain text без раскрытия имён или ID других гостей и названий групп доступа; сбои доставки (например, если пользователь заблокировал бота) не влияют на работу HTTP API.

## Правила видимости и приватности

- Если у желания поле `group_ids` пустое или отсутствует, оно общее и доступно всем.
- Если выбраны группы, желание видят только пользователи, входящие хотя бы в одну из них.
- Владелец всегда видит все собственные желания и все созданные поводы; гость видит только те поводы, в которых есть хотя бы одно доступное ему желание.
- Фильтрация выполняется в Worker, а не только в HTML.
- Скрытое желание нельзя забронировать или скопировать по известному ID: Worker возвращает `404`.
- При изменении аудитории желания, удалении группы или удалении пользователя из группы недоступные брони и участия автоматически отменяются.
- Чужие Telegram ID в API (`booked_by`, `participants`, `reusable_givers`) маскируются значением `-1`.
- Изображения из KV доступны владельцу и гостям только в рамках тех же правил видимости, что и связанные желания; при копировании чужого подарка создаётся независимая копия изображения с владельцем-получателем.
- Telegram `initData` проверяется на Worker через HMAC-SHA256. Подпись и срок действия проверяются для каждого защищённого запроса.

## Архитектура

```text
Telegram Mini App / Telegram Bot
              |
              v
        GitHub Pages
          index.html
              |
              | HTTPS + X-Telegram-Init-Data
              v
      Cloudflare Workers
           worker.js
              |
              v
        Cloudflare KV
    JSON, социальные данные,
        бинарные изображения
```

Архитектурное ограничение: **R2 не используется**. Вишлисты, профили, подписки, группы, поводы, участия и фотографии хранятся только в KV.

### Компоненты

| Файл | Назначение |
| --- | --- |
| `index.html` | Интерфейс Mini App, явное браузерное демо, работа с API и защищённая загрузка изображений |
| `worker.js` | Telegram webhook, проверка `initData`, API, права доступа, кастомные группы, поводы, уведомления и работа с KV |
| `wrangler.toml` | Конфигурация Worker, привязка KV и Secrets Store |
| `tests/worker.test.mjs` | Backend-тесты с KV в памяти |
| `tests/browser-telegram.js` | Сценарии Telegram-режима с mock API |
| `tests/browser-demo.js` | Сценарии демо, социальных функций и адаптивности |
| `tests/browser-runner.mjs` | Локальный HTTP-сервер и запуск браузерных сценариев |

### Конфигурация

- KV доступен в Worker как `env.DB`.
- Токен бота хранится только в Cloudflare Secret или Secrets Store под именем `BOT_TOKEN` и читается через `env.BOT_TOKEN`.
- Публичный адрес Mini App задаётся переменной `WEBAPP_URL`.
- Токен нельзя добавлять в `index.html`, `worker.js`, `wrangler.toml`, GitHub или документацию.

## Хранение данных в KV

| Ключ | Содержимое |
| --- | --- |
| `user:<ownerId>` | Профиль владельца, массив поводов `occasions` и массив желаний `gifts` (с `group_ids`, `occasion_ids`, `is_reusable`, `reusable_givers`) |
| `img:<imageId>` | Бинарное изображение и metadata владельца |
| `config:bot` | Временный кеш username бота |
| `participations:<viewerId>` | Индекс броней (`book`), совместных сборов (`crowdfund`) и многоразовых подарков (`reusable`) пользователя |
| `directory:<userId>` | Telegram ID, имя и username пользователя |
| `username:<normalizedUsername>` | Соответствие нормализованного username и Telegram ID |
| `subscriptions:<viewerId>` | Список ID владельцев, на которых подписан пользователь |
| `subscribers:<ownerId>` | Обратный индекс ID подписчиков владельца вишлиста |
| `groups:<ownerId>` | Кастомные группы владельца (`items: [{ id, name, memberIds }]`, до 20 групп) |
| `notify_prefs:<userId>` | Настройки уведомлений пользователя (`bookings`, `new_gifts`) |
| `selection:<requestId>` | Одноразовый запрос выбора пользователя в Telegram, TTL 900 секунд |

Старые желания без `group_ids`, `occasion_ids` и `is_reusable`, а также старые группы без `name` поддерживаются без миграции.

## HTTP API

Все маршруты данных, кроме healthcheck, конфигурации бота и webhook, требуют заголовок `X-Telegram-Init-Data`.

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /` | Проверка состояния сервиса |
| `POST /` | Telegram webhook, `/start` (включая `list_<id>_occ_<occId>`), `/notifications`, `callback_query` и выбор пользователя |
| `GET /api/health` | Healthcheck |
| `GET /api/config` | Username бота |
| `GET /api/gifts?owner_id=<id>` | Получение вишлиста, видимых поводов и (для владельца) групп |
| `POST /api/gifts` | CRUD желаний и поводов; бронирование, участие в сборе, многоразовые отметки и копирование чужого желания |
| `GET/POST /api/data` | Alias для `/api/gifts` |
| `GET /api/participations` | Список «Я участвую» |
| `GET/POST /api/social` | Подписки и управление кастомными группами |
| `POST /api/upload` | Загрузка изображения в KV |
| `GET /api/img/<imageId>` | Авторизованное получение изображения |

- Действия владельца в `/api/gifts`: `add`, `update`, `delete`, `toggle_gifted`, `save_occasion`, `delete_occasion`.
- Действия гостя в `/api/gifts`: `toggle_book`, `toggle_crowdfund`, `copy_gift`.
- Действия в `/api/social`: `subscribe`, `unsubscribe`, `add_group_member`, `remove_group_member`, `create_group`, `rename_group`, `delete_group`.

## Текущие ограничения

- Изображения: только WebP и JPEG, не более 512 КБ.
- Не более 8 тегов на желание, до 20 групп и до 20 поводов на пользователя.
- Флаги `is_crowdfund` и `is_reusable` взаимоисключающие.
- Нет денежных переводов и автоматической синхронизации телефонной книги.
- Bot API не позволяет произвольно преобразовать любой username в ID; для неизвестного username используется встроенный Telegram user picker.
- Браузерное демо хранит изменения локально и не заменяет production API при ошибке.

## Автоматические тесты

Требуется Node.js 20 или новее.

### Установка и полный запуск

```bash
npm install
npx playwright install chromium
npm test
```

### Только backend

```bash
npm run test:worker
```

Backend-тесты не требуют установки пакетов, настоящего Cloudflare KV или реального токена. Они импортируют `worker.js`, используют тестовый секрет и реализацию KV в памяти.

Покрываются 20 групп сценариев:

1. CORS, healthcheck и неизвестные маршруты.
2. Проверка Telegram `initData`, подписи и срока действия.
3. Профиль владельца пустого чужого вишлиста.
4. CRUD желаний, валидация и права владельца.
5. Бронирование, совместные сборы и маскирование Telegram ID.
6. Уровни желания, необязательные ссылки и теги.
7. Индекс участий при бронировании, отмене и удалении.
8. Восстановление участий и очистка устаревших записей.
9. Подписки, группы и серверная фильтрация по аудитории.
10. Выбор пользователя в Telegram и завершение социальных действий.
11. Загрузка, доступ, кеширование и удаление KV-изображений.
12. Кеш конфигурации бота и deep link `/start list_<ownerId>`.
13. Уведомления бота при удалении подарка, отметке «Подарили» и редактировании подарка.
14. Сгруппированные уведомления при исключении гостя из группы доступа.
15. Рассылка о новых желаниях с учётом обратного индекса подписчиков, групп и лимита уведомлений.
16. Настройка уведомлений через `/notifications` и `callback_query`, а также устойчивость к ошибкам Telegram API (`403`).
17. Кастомные группы приватности: CRUD, лимиты, дубли, обратная совместимость со старыми группами и защита при удалённой группе в `users_shared`.
18. Поводы: CRUD, валидация, скрытие приватных поводов от гостей и deep link `/start list_<ownerId>_occ_<occId>`.
19. Многоразовые подарки: взаимоисключение с `is_crowdfund`, независимая отметка несколькими гостями, маскировка ID и синхронизация `participations`.
20. Копирование чужого подарка: проверка приватности (`404`), сброс чужих полей и независимое клонирование KV-изображения.

### Только браузерные сценарии

```bash
npm install
npx playwright install chromium
npm run test:browser
```

Запускатель поднимает временный локальный HTTP-сервер на свободном порту и открывает актуальный `index.html` в Chromium. Telegram SDK, Worker API и внешние ресурсы заменяются тестовыми заглушками.

## Ручная проверка в Telegram

Для полного сценария нужны два собственных аккаунта Telegram:

1. Основной аккаунт открывает бота, создаёт желание и отправляет ссылку второму аккаунту.
2. Второй аккаунт открывает вишлист и проверяет имя и `@username` владельца.
3. Второй аккаунт бронирует обычный подарок, отмечает многоразовый и присоединяется к сбору.
4. Основной аккаунт видит занятость и счётчики, но не имена гостей.
5. Второй аккаунт проверяет раздел «Я участвую», копирование желания себе и отмену участия.
6. Владелец ограничивает желание кастомной группой и поводом, проверяя, что пользователь вне группы не видит ни подарок, ни приватный повод.
7. Для неизвестного username проверяется выбор человека через Telegram и последующее добавление ID.

Автоматические браузерные тесты не заменяют эту проверку реального Telegram user picker и webhook.

## Публикация

- GitHub Pages публикует `index.html`.
- Cloudflare Workers Builds собирает Worker из репозитория.
- После изменения следует дождаться успешных автоматических сборок, проверить живую Pages-версию и выполнить `npm test` до или после публикации.
- При выпуске изменений приватности дополнительно нужен ручной сценарий с двумя Telegram-аккаунтами.
